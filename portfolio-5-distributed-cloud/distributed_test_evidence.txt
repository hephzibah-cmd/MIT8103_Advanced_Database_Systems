7. CAP / PACELC ANALYSIS (as configured)
----------------------------------------------------------------------
  Topology: single primary + 2 ASYNC hot standbys, manual failover.
  Partition (P), primary side: primary keeps accepting writes (available);
     replicas cut off from it keep serving reads that grow stale.
  Partition, replica side: reads stay available but are not linearizable;
     writes are unavailable there (standbys are read-only).
  Else (E, no partition): async replication trades replica consistency for
     commit latency => PACELC PA/EL for replica reads.
  Ledger correctness comes from routing ALL ledger writes and balance-before-
     debit reads to the one primary (single-node ACID), not from replication.
  Failover RPO > 0 while async: commits not yet streamed are lost on promotion.
  Target for ledger (PC/EC, RPO=0): synchronous_standby_names =
     'ANY 1 (replica_1, replica_2)' — writes block rather than risk loss.
